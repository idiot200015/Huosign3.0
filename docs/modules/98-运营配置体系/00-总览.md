## 1. 文档定位

本目录集中梳理火象 App 内所有"由运营后台配置"的展示位、内容资源、规则参数。每个配置点对应一个独立子文档，详细描述：

- 用户端展示规则（已在用户端文档中描述，本目录仅做配置项视角的补充）
- 后台配置项清单（字段、类型、限制、默认值）
- 配置生效规则（时间窗、启用开关、优先级）
- 异常处理（配置缺失、加载失败、目标无效）

## 3. 关于运营后台

火象 3.0 的"运营后台"为独立项目（前端管理界面、后端管理服务），**不在本 PRD 范围内**。本目录文档描述以下内容：

1. **配置数据结构**：每个配置项的字段定义（用于前后端约定数据契约）
2. **配置生效规则**：时间窗、启用、优先级、频次等
3. **App 端消费规则**：App 端如何使用这些配置数据、如何容错

**不描述的内容**：运营后台的具体页面布局、操作流程、权限管理、审核流程等。

## 5. 通用配置规范

所有配置项遵循以下通用规范：

### 5.1 通用字段

每条配置应至少包含以下字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| 唯一 ID | string | 配置项唯一标识 |
| 启用状态 | boolean | 是否启用（运营手动开关） |
| 生效时间窗 | datetime | 开始时间 + 结束时间 |
| 优先级 | int | 同类配置共存时排序 |
| 创建时间 / 创建人 | metadata | 审计字段 |
| 更新时间 / 更新人 | metadata | 审计字段 |

### 5.2 时间窗规则

- 时间统一使用服务器时间（UTC+8）
- 精确到秒
- 开始时间 = 配置生效起点（含）
- 结束时间 = 配置生效终点（含）
- 时间窗外配置自动失效，无需手动下线
- 启用状态可独立于时间窗手动控制（即使在时间窗内，启用状态为 false 时不生效）

### 5.3 优先级规则

- 数值越大优先级越高
- 同优先级按创建时间倒序

### 5.4 配置缺失兜底

App 端消费配置时遵循统一兜底原则：

- 配置接口失败 → 不展示该配置位，按"无配置"处理
- 配置内容字段缺失 → 不展示，按"无配置"处理
- 配置内容引用的资源加载失败（如图片）→ 不展示
- **不展示空白页 / 占位图 / 默认兜底图**（除非该配置位有明确的兜底设计）

### 5.5 配置变更生效

- 后台配置保存后立即生效（用户下次请求时获取新配置）
- 已展示中的内容不强制刷新（如已展示的开屏广告继续显示完毕）
- 紧急下线时由后台管理员通过手动关闭"启用状态"实现
