## 1. 模块定位

现金奖励中心承载用户**现金挑战**的任务列表与奖金流水。

3.0 中现金挑战是 4 条独立奖励流之一，与升级任务（XP）、补贴金（盈利分成）、积分（积分商城）独立。

核心特征：

- 现金挑战共 **15 个**，按编号顺序解锁（时间轴形态展示）
- 每个挑战对应**邀请门槛**（需邀请一定数量好友达到对应阶段）
- 用户**不主动提现**，由运营每月审核后打款到支付宝（实名失败的用户不予打款）
- 总奖金池约 2 万元

## 2. 入口与跳转

### 入口

- 训练主页 → 实训账户卡片底部并列入口 → "现金奖励中心"

### 出口

| 出口 | 触发条件 |
|---|---|

| 邀请海报弹窗 | 用户在挑战详情中点击"去邀请解锁" |

| 返回训练主页 | 顶部返回按钮 |

## 3. 页面结构

### 3.1 整体布局

| 顺序 | 区域 | 说明 |
|---|---|---|
| 1 | 顶部导航栏 | 返回 + 标题"现金奖励中心" |
| 2 | 顶部奖金概览 | 累计获得 / 待审核 / 已打款 |
| 3 | Tab 切换 | 任务列表 / 奖金流水 |
| 4 | 主体内容区 | 按 Tab 切换不同内容 |

底部**不显示**"去提现"按钮（用户不主动提现）。

### 3.2 顶部奖金概览

居中卡片展示用户的累计奖金数据：

| 数据 | 说明 |
|---|---|
| 累计获得 | 用户已完成挑战累计获得的奖金总额（含未审核、已打款）|
| 待审核 | 已完成挑战等待运营月度审核的金额 |
| 已打款 | 运营已审核通过且已打款到支付宝的金额 |

视觉规则：3 个数据并排展示，使用大字号数字。

## 4. Tab 1：任务列表（时间轴形态）

### 4.1 时间轴布局

15 个现金挑战按编号顺序展示，使用**纵向时间轴**形态：

| 元素 | 说明 |
|---|---|
| 时间轴主线 | 左侧纵向直线，连接所有节点 |
| 节点 | 每个挑战对应一个节点圆点 |
| 节点文字 | 节点右侧展示挑战编号 + 名称 + 状态 |

**视觉规则**：

| 节点状态 | 圆点视觉 |
|---|---|
| 已完成 | 主色 `#E72737` 实心圆 |
| 进行中 | 主色描边 + 内白 |
| 已解锁未开始 | 主色描边 |
| 未解锁 | 灰色 `#D1D1D1` 实心圆 + 锁图标 |
| 已失败 | `#F44336` 实心圆 + × 标识 |

时间轴**严格按挑战编号顺序展示**（不可跳过），符合"逐级解锁"的产品逻辑。

### 4.2 节点卡片字段

每个节点的右侧卡片展示：

| 字段 | 说明 |
|---|---|
| 编号 + 名称 | 如 "挑战 03 - 持仓时长挑战" |
| 邀请门槛 | "需邀请 3 人启动实训账户"（进度展示如 "1/3"）|
| 任务内容 | 简短描述（如 "持仓时长 ≥ 1 小时" 等）|
| 奖金额 | 如 "¥500" |
| 状态标签 | 未解锁 / 已解锁未开始 / 进行中 / 已完成 / 已失败 |
| 主按钮（按状态变化）| 详见下方 |

### 4.3 状态对应的按钮

| 状态 | 主按钮 | 点击行为 |
|---|---|---|
| 未解锁 | "去邀请解锁" | 弹出现金挑战详情半框 |
| 已解锁未开始 | "开始挑战" | 弹出现金挑战详情半框 |
| 进行中 | "查看进度" | 弹出现金挑战详情半框 |
| 已完成 | 无按钮（标签"已完成"+ 奖金到账状态）| 卡片可点击展开详情 |
| 已失败 | "重新挑战" | 弹出现金挑战详情半框 |

### 4.4 现金挑战详情半框

点击节点或按钮时弹出半框，展示完整挑战详情。

**半框结构**：

| 区域 | 内容 |
|---|---|
| 顶部 | 挑战编号 + 名称 + 关闭按钮 |
| 状态标签 | 当前状态（未解锁 / 已解锁 / 进行中 / 已完成 / 已失败）|
| 邀请门槛区 | 邀请要求 + 当前进度 + "去邀请解锁"按钮（未解锁时）|
| 任务内容区 | 任务详细说明 |
| 奖励信息 | 奖金额 + 结算说明（"完成后由运营审核打款支付宝"）|
| 主按钮 | 按状态变化（去邀请 / 开始挑战 / 重新挑战 / 查看奖金）|

### 4.5 现金挑战的互斥规则

现金挑战属于"任务三类"之一（与日常任务、实训任务互斥）：

- 用户接受现金挑战时，如已有其他进行中任务，按通用互斥规则提示
- 详见 [04-任务详情半框](./04-任务详情半框.md) 互斥处理章节

### 4.6 现金挑战的归属规则

接受现金挑战前，如有"待追溯"邀请用户，弹出归属告知：

```
弹窗：
标题：邀请归属说明
正文：你之前已邀请 X 位好友。开始本次现金挑战后，这些好友将归于"现金邀请"类，参与现金挑战的邀请进度统计，归属一经确定不可更改。
按钮：取消 / 我知道了
```

详见 [02-邀请中心](../02-跨Tab通用/02-邀请中心.md) 第 3.4 节。

## 5. Tab 2：奖金流水

### 5.1 流水列表

按完成时间倒序展示用户已完成挑战的奖金流水。

每条流水卡片展示：

| 字段 | 说明 |
|---|---|
| 挑战编号 + 名称 | 如 "挑战 03 - 持仓时长挑战" |
| 完成时间 | 用户完成挑战的时间戳 |
| 奖金额 | 如 "+¥500" |
| 结算状态 | 待审核 / 已审核 / 已打款 / 打款失败 |
| 备注 | 仅打款失败时展示原因（如"实名信息缺失"）|

### 5.2 状态详解

| 状态 | 含义 |
|---|---|
| 待审核 | 用户完成挑战，等待运营月度审核 |
| 已审核 | 运营已审核通过，等待打款 |
| 已打款 | 资金已转账到用户支付宝 |
| 打款失败 | 因用户实名缺失等原因未能打款 |

### 5.3 加载与排序

| 项 | 规则 |
|---|---|
| 排序 | 完成时间倒序 |
| 默认加载 | 全部展示（最多 15 条）|
| 上拉加载 | 不需要（数据量小，一次加载完）|
| 不支持筛选 | V1 简化 |

### 5.4 流水点击行为

点击单条流水：
- 不展开详情（数据已经全部展示）
- 仅"打款失败"状态下，可点击"了解详情"展开失败原因和处理建议（如"请前往实名认证 → 提交实名信息"）

## 6. 关键规则

### 6.1 不主动提现

3.0 中**用户不主动提现**：

- 不展示"去提现"按钮
- 不需要用户绑定支付宝
- 用户的实训账户领取流程中已收集支付宝信息（如适用）
- 运营每月审核 → 自动打款 → 流水状态更新

### 6.2 实名校验

不在 App 内拦截：

- 用户进入现金奖励中心、查看挑战详情、完成挑战，**全程不拦截**
- 仅在运营审核环节，无实名信息的用户不予打款，流水状态变为"打款失败"
- 用户在流水中看到"打款失败"提示后，可主动去实名认证

### 6.3 奖金的累计规则

- 每完成一个挑战，奖金立即记入"累计获得"
- 但需要等待运营审核才能打款（"待审核"状态）
- 失败的挑战可以重新挑战，但**不重复领取奖金**（同一个挑战只能拿一次奖金）

## 7. 异常态

| 异常 | 表现 | 处理 |
|---|---|---|
| 列表加载失败 | 时间轴 / 流水为空 | 显示"加载失败，下拉刷新重试" |
| 详情半框加载失败 | 点击节点无响应 | Toast"加载失败，请重试" |
| 邀请进度更新延迟 | 用户已邀请但进度未更新 | 用户下拉刷新可刷新数据；后端推送主动更新更优 |
| 奖金计算异常 | 概览数字异常 | 后台监控告警，前端显示最近一次成功值 |

## 8. 接口约束

| 能力 | 说明 |
|---|---|
| 拉取奖金概览 | 返回累计获得 / 待审核 / 已打款 数据 |
| 拉取现金挑战列表 | 返回 15 个挑战的状态 + 邀请进度 + 奖金 |
| 拉取奖金流水 | 返回用户已完成挑战的流水 |
| 拉取挑战详情 | 根据挑战 ID 返回完整详情 |
| 接受现金挑战 | 用户接受挑战，记录用户当前任务为该挑战 |

接口的具体定义、字段、协议由后端开发设计，本文档仅描述业务诉求。

---

## 9. 合规要求

| 要求 | 说明 |
|---|---|
| 实名后才可打款 | 运营审核环节强制执行 |
| 文案合规 | 现金挑战相关文案需通过合规审核（避免诱导分享、过度激励）|
| 奖金到账时效 | 用户协议中明示打款时效（每月审核 + 打款，详细周期 [待运营提供]）|
| 不打款情况告知 | 实名失败 / 违规等情况导致不打款时，需在流水中明确告知用户 |
