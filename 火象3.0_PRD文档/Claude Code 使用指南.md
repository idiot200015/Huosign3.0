# Claude Code 使用指南

本指南用于火象 3.0 HTML 原型项目，帮助你高效使用 Claude Code 生成可预览原型。

---

## 一、环境准备

### 1.1 仓库结构

建议你的 GitHub 仓库结构如下：

```
huoxiang-3.0-prototype/
├── CLAUDE.md                    # 项目级提示词（必备，已提供）
├── README.md                    # 仓库说明
├── docs/                        # PRD 文档目录
│   ├── PRD.md
│   └── modules/
│       ├── 01-账号生命周期/
│       ├── 98-运营配置体系/
│       └── 99-全局规范/
├── prototypes/                  # HTML 原型输出目录
│   ├── index.html              # 总入口
│   ├── _placeholder.html       # 占位页
│   └── *.html
├── references/                  # 参考资料（设计稿、截图等）
│   ├── 火象V3.0设计规范.pdf
│   └── 视觉参考图/
└── .gitignore
```

### 1.2 初次拉取仓库

```bash
git clone https://github.com/<your-username>/huoxiang-3.0-prototype.git
cd huoxiang-3.0-prototype
```

### 1.3 启动 Claude Code

在仓库根目录执行：

```bash
claude
```

Claude Code 会自动加载 `CLAUDE.md`，无需手动指定。

## 二、单页面生成提示词模板

### 2.1 基础模板

```
请根据 docs/modules/<模块路径>/<文档名>.md 生成 HTML 原型。

输出文件：prototypes/<文件名>.html

要求：
1. 严格按照 docs/modules/99-全局规范/01-视觉规范.md 的视觉规范实现
2. 移动端视口模拟（375 × 812）
3. 使用 mock 数据展示具体内容
4. 跳转目标暂时指向 _placeholder.html，未实现的页面占位

完成后告诉我已生成的文件，并简要说明如何在浏览器中预览。
```

### 2.2 实例：生成启动页

```
请根据 docs/modules/01-账号生命周期/01-启动页.md 生成 HTML 原型。

输出文件：prototypes/01-启动页.html

要求：
1. 严格按照视觉规范
2. 模拟启动页 1.5 秒展示，然后用 JS setTimeout 自动跳转
3. 强更弹窗 / 隐私弹窗用页面内的 modal 演示，提供"模拟触发"按钮便于评审
4. 跳转目标：
   - 隐私同意 → 02-开屏广告.html（如已存在），否则 _placeholder.html
   - 强更立即更新 → 提示"模拟跳转应用市场"
5. 模拟手机视口（375×812 居中容器）

完成后更新 prototypes/index.html 加入此原型链接。
```

## 三、多页面联动提示词模板

### 3.1 完整流程演示

当需要演示一个完整业务流程（如账号注销全流程）时：

```
请根据以下文档生成账号注销的完整流程原型：

文档：
- docs/modules/01-账号生命周期/06-账号注销.md
- docs/modules/06-我的Tab/03-设置.md

输出文件（4 个）：
1. prototypes/06-我的页.html         # 含"设置"入口
2. prototypes/07-设置页.html         # 含"账号注销"入口
3. prototypes/08-注销须知页.html     # 注销影响清单
4. prototypes/09-注销验证页.html     # 二次验证

各页面间通过 a 链接跳转，形成完整流程。每个页面顶部加返回按钮。

完成后更新 prototypes/index.html。
```

### 3.2 状态分支演示

某些页面有多个状态（如任务有"进行中 / 失败 / 成功"），可以这样让 Claude Code 展示：

```
请根据 docs/modules/04-训练Tab/04-任务详情半框.md 生成任务详情原型。

需要展示 4 种状态：
1. prototypes/任务详情-未开始.html
2. prototypes/任务详情-进行中.html
3. prototypes/任务详情-挑战失败.html
4. prototypes/任务详情-挑战成功.html

每种状态独立 HTML，便于评审对比。
```

## 四、维护与迭代提示词

### 4.1 修改已生成的页面

```
请修改 prototypes/01-启动页.html，调整以下内容：
1. Slogan 文案改为"金融教育，从模拟开始"
2. 启动页停留时间从 1.5 秒改为 2 秒
3. 背景颜色调整为渐变（从 #FFFFFF 到 #F8F9FC）

不要修改其他文件。
```

### 4.2 统一美化（第二轮）

第一轮"骨架 + 跳转"完成后，可以统一美化：

```
请对 prototypes/ 目录下所有 HTML 文件进行统一美化，要求：
1. 所有按钮使用统一的圆角和阴影
2. 所有卡片背景统一使用 #F0F2F8
3. 所有文字字号严格按视觉规范
4. 所有间距使用 4 的倍数

不要修改业务逻辑和跳转关系，仅调整视觉。
```

### 4.3 索引页更新

```
请更新 prototypes/index.html，按"账号生命周期 / 跨 Tab 通用 / 4 大 Tab / 全局组件"分类组织已完成的原型链接。
```

## 五、Claude Code 工作流建议

### 5.1 推荐节奏

| 阶段 | 工作内容 | 时长建议 |
|---|---|---|
| 阶段 1：基础页面 | 启动页、登录、注册、首页 | 1 周 |
| 阶段 2：训练 Tab | 训练主页、成长模块、等级详情、任务、奖励中心 | 1 周 |
| 阶段 3：学习 / 我的 Tab | 学习页、课程、我的页、设置 | 1 周 |
| 阶段 4：弹窗与异常态 | 各类弹窗、空状态、异常态 | 3 天 |
| 阶段 5：统一美化 | 视觉统一、动效、细节 | 3 天 |

### 5.2 评审节奏

每完成一个阶段：
1. 推送到 GitHub
2. 部署到 GitHub Pages（仓库设置中开启）
3. 把 Pages URL 发给评审同学

GitHub Pages 部署：仓库 Settings → Pages → Source 选择 `main` 分支 → `/prototypes` 目录（或 `/`）→ 保存。

## 六、常见问题

### Q1. Claude Code 生成的 HTML 在飞书云文档里能预览吗？

不能。HTML 原型用浏览器预览。飞书云文档用于查看 PRD 文档（Markdown）。两者用途不同。

### Q2. 生成的页面在不同浏览器表现不一致？

原型仅在 Chrome / Edge / Safari 现代版本上保证效果。不需要兼容 IE。

### Q3. Claude Code 生成的代码我看不懂怎么办？

让 Claude Code 在代码中加详细中文注释，或要求它在生成完成后输出"代码逻辑说明文档"。

### Q4. 怎么让原型支持手机真机预览？

部署到 GitHub Pages 后，用手机浏览器打开对应链接即可。或者在本机启动 `python -m http.server 8000`，手机连同 WiFi 后访问 `http://<电脑IP>:8000/prototypes/`。

### Q5. PRD 文档有更新，原型需要重做吗？

不需要全部重做。让 Claude Code 针对变更的页面单独修改：

```
docs/modules/<路径>/<文档>.md 已更新，主要变更是 [说明变更内容]。
请同步修改 prototypes/<文件>.html，仅修改受影响的部分。
```

## 八、注意事项

1. **每次启动 Claude Code 前，确保 docs 目录是最新版本**（git pull）
2. **遇到信息缺失，让 Claude Code 询问而不是猜测**
3. **不要让 Claude Code 一次生成超过 5 个页面**，质量会下降
4. **生成后浏览器实际打开看一眼**，文档说"完成"不代表 100% 正确
5. **重要修改前先 git commit**，方便回滚
