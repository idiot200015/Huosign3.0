# 火象 3.0 HTML 原型项目规则

本文件为 Claude Code 在本仓库工作时遵循的全局规则。每次对话自动加载，无需重复说明。

---

## 1. 项目目标

生成火象 3.0 各页面的**可预览 HTML 原型**。每个页面独立 HTML 文件，浏览器直接打开即可预览，不依赖构建工具。

原型用途：作为高保真原型供产品评审、UI 参考、开发联调。**不是最终生产代码**。

---

## 2. 文档来源

所有页面需求来自 `docs/modules/` 目录下的 PRD 文档。生成代码前**必须先阅读对应文档**，包括：

1. 目标页面的具体文档（如 `docs/modules/01-账号生命周期/01-启动页.md`）
2. 顶层概览文档 `docs/PRD.md`
3. 全局视觉规范 `docs/modules/99-全局规范/01-视觉规范.md`
4. 相关的运营配置文档（如开屏广告需读 `docs/modules/98-运营配置体系/01-开屏广告配置.md`）

如果文档之间有冲突或缺失关键信息，**停止生成，明确询问用户**，不要自行猜测。

---

## 3. 技术栈

| 项 | 规则 |
|---|---|
| 语言 | HTML + CSS + JS（全部内联在单文件中） |
| 框架 | 不使用 React / Vue / Angular |
| 包管理 | 不使用 npm，所有依赖通过 CDN 引入 |
| CSS | 使用 Tailwind CSS（CDN 引入），结合自定义 CSS 实现品牌视觉 |
| JS | 原生 JavaScript（ES6+），不使用 jQuery |
| 字体 | 使用系统字体栈，中文 PingFang SC 优先 |

CDN 地址（请使用最新稳定版）：

```html
<script src="https://cdn.tailwindcss.com"></script>
```

## 4. 视觉规范（必须严格遵循）

详细规范见 `docs/modules/99-全局规范/01-视觉规范.md`。核心要点：

### 4.1 设计稿基准

- 设计稿尺寸：**375 × 812 px**
- 移动端视口模拟：在桌面浏览器预览时，使用 `<meta name="viewport">` + 容器宽度 375px 居中显示
- 页边距：16 px

### 4.2 色彩

| 名称 | 色值 |
|---|---|
| 主色（火象红） | `#E72737` |
| 主色按下 | `#C51826` |
| 警告 | `#FF9F1C` |
| 信息 | `#3A86FF` |
| 成功 | `#2DC771` |
| 错误 | `#F44336` |
| 一级文字 | `#333333` |
| 二级文字 | `#666666` |
| 三级文字 | `#999999` |
| 禁用 | `#D1D1D1` |
| 分割线 | `#E9EDF4` |
| 卡片背景 | `#F0F2F8` |
| 全局背景 | `#F8F9FC` |

### 4.3 字号

`18px Semibold` / `16px Medium` / `14px Regular` / `12px Regular` / `10px Regular`

### 4.4 圆角

`4 / 8 / 12 / 16 px`，弹窗用 16 px

### 4.5 按钮高度

`28 / 32 / 40 / 48 px`

### 4.6 间距

间距使用 4 的倍数：`4 / 8 / 12 / 16 / 20 / 24 px`

## 5. 文件组织

### 5.1 目录结构

```
prototypes/
├── index.html              # 总入口，列出所有原型链接
├── _placeholder.html       # 占位页（未实现的页面跳转目标）
├── _shared/
│   ├── style.css           # 公共样式（可选，仅复用度极高时使用）
│   └── mock-data.js        # 公共 mock 数据（可选）
├── 01-启动页.html
├── 02-开屏广告.html
└── ...
```

### 5.2 命名规则

- 文件名与 PRD 文档一致（如 PRD 文档为 `01-启动页.md`，原型为 `01-启动页.html`）
- 用中文命名，方便识别
- 编号前缀保留，便于排序
- **不使用空格、特殊字符**

### 5.3 单文件优先

- 每个页面**单文件**，HTML + CSS + JS 全部内联
- 公共样式 / JS **可选**抽出到 `_shared/`，仅当复用度极高时
- 不为了"工程化"而过度拆分

---

## 6. 数据与接口

### 6.1 Mock 数据

- 所有展示数据使用 mock 数据**写死在 HTML 内**
- mock 数据应符合 PRD 文档描述的字段含义
- 数值使用真实场景的合理值（如等级 Lv3、XP 230/630）

### 6.2 接口

- **不调用真实接口**
- 不实现真实业务逻辑（如登录验证、表单提交、数据持久化）
- 表单提交后用模态框 / Toast 模拟成功，不调用接口

---

## 7. 交互实现

### 7.1 跳转关系

- 页面间跳转使用 `<a href="">` 实现
- 目标指向其他 HTML 文件相对路径
- 未实现的页面跳转到 `_placeholder.html`

### 7.2 页面内交互

- 复杂状态切换用简单的 JS 实现（如 Tab 切换、表单字段联动、弹窗显示隐藏）
- 不实现真实的网络请求、不引入状态管理库
- 优先用原生 JS 的 DOM API

### 7.3 动画

- 不追求复杂动画
- 关键交互的过渡用 CSS `transition` 实现
- 弹窗出现 / 消失使用淡入淡出

---

## 8. 移动端模拟

桌面浏览器预览原型时，建议在 `index.html` 中使用 iframe 模拟手机视口：

```html
<iframe src="01-启动页.html" 
        style="width: 375px; height: 812px; 
               border: 1px solid #E9EDF4; 
               border-radius: 12px;
               margin: 0 auto; display: block;">
</iframe>
```

每个独立 HTML 文件在 `<body>` 内用 max-width: 375px 居中容器布局：

```html
<body style="margin: 0; background: #ccc;">
  <div style="max-width: 375px; min-height: 100vh; margin: 0 auto; background: #fff;">
    <!-- 页面内容 -->
  </div>
</body>
```

## 9. 代码风格

- HTML 使用语义化标签（`<header>` / `<nav>` / `<main>` / `<section>` 等）
- CSS 类名使用 Tailwind 工具类优先；自定义样式用 `kebab-case`
- JavaScript 使用 ES6+ 语法（`const` / `let` / 箭头函数 / 模板字符串）
- 注释清晰：每个主要区块、复杂逻辑有中文注释
- 避免冗余代码，单文件控制在 500 行以内（除非页面确实复杂）

---

## 10. 输出规则

### 10.1 一次任务范围

- 每次任务**只生成一个或几个相关页面**
- 不主动批量生成多个无关页面
- 不主动修改其他已存在的文件（除非用户明确要求）

### 10.2 输出后告知

每次任务完成后，输出以下内容：

1. 已生成的文件列表
2. 每个文件的简要说明（实现了什么）
3. 预览方式（如何在浏览器中查看）
4. 已知的不足或简化点（如果有）

### 10.3 index.html 维护

每生成新页面后，更新 `prototypes/index.html`：

- 在已完成原型列表中加入新条目
- 提供该页面的可点击链接
- 简要说明页面内容

---

## 11. 信息缺失时的处理

如果 PRD 文档中某些信息缺失（标记为 [待补充] 或未提及）：

1. **不自行猜测**
2. 明确告知用户哪些信息缺失
3. 询问用户如何处理：
   - 用 placeholder 代替（如"占位文案"、灰色矩形图）
   - 使用合理的默认值（说明使用了什么默认值）
   - 暂停生成等待补充

---

## 12. 不允许的行为

- ❌ 不要为了"完整性"自行补充 PRD 中未提及的功能
- ❌ 不要修改 `docs/` 目录下的任何文档
- ❌ 不要使用真实用户数据
- ❌ 不要在原型中包含真实的接口域名 / 密钥 / 敏感配置
- ❌ 不要为原型添加构建配置（webpack / vite 等）
- ❌ 不要把原型当作生产代码，不需要做单元测试 / E2E 测试
