## 1. 页面定位

训练 Tab 是火象 3.0 的**核心业务页面**，承载用户成长（升级 / 任务 / 训练）的全部入口。所有训练相关动作（接任务、查看任务、做任务、查训练历史、领取奖励）都从这里发起。

定位区别：
- **首页**：流量与内容消费入口
- **训练页**：业务执行核心
- **学习页**：课程消费
- **我的页**：个人中心与设置

## 3. 页面结构

### 3.1 整体布局

页面采用**纵向滚动**布局，从上到下：

| 顺序 | 区域 | 高度（参考）| 说明 |
|---|---|---|---|
| 1 | 顶部导航栏 | 44px | 标题"训练"，无其他元素 |
| 2 | 成长模块 | 约 1/5 屏高（约 160px）| 等级 + XP + 邀请进度 + CTA |
| 3 | 当前任务横条 | 约 80px（无任务时隐藏）| 进行中任务 + 失败挽留态 |
| 4 | 实训账户卡片 | 不定（含数据 + 任务区 + 入口）| |
| 5 | 模拟账户卡片 | 不定（含数据 + 任务区）| |
| 6 | 任务数据概览 | 约 64px | 进行中 / 已完成 / 待开启 |
| 7 | 训练历史 | 不定（默认 3 条 + 查看全部）| |
| - | 底部"训练"按钮 | 56px | **固定在屏幕底部**，不随滚动 |

### 3.2 顶部导航栏

| 元素 | 内容 |
|---|---|
| 左侧 | 无 |
| 标题 | "训练"（居中或左对齐均可，按 UI 规范）|
| 右侧 | 无 |

### 3.3 成长模块

详见 [02-成长模块](./02-成长模块.md)。

### 3.4 当前任务横条

**展示规则**：

| 场景 | 显示 |
|---|---|
| 用户有进行中任务 | 显示横条（进行中状态）|
| 用户当前任务为"挑战失败"挽留态 | 显示横条（挽留状态）|
| 用户无任何进行中任务、无挽留态任务 | **整体隐藏**，下方内容上移 |

**进行中状态**：

| 元素 | 内容 |
|---|---|
| 任务类型标签 | "Lv X - 模拟" / "Lv X - 实训" / "现金挑战" |
| 任务名称 | 任务名（最多 1 行） |
| 任务进度 | 进度文字（如 "已完成 2/3 笔交易"）|
| 状态标签 | "进行中"（绿色）|
| 点击行为 | 跳转 [04-任务详情半框](./04-任务详情半框.md) |

**挑战失败挽留态**：

| 元素 | 内容 |
|---|---|
| 任务类型标签 | 同上 |
| 任务名称 | 同上 |
| 状态标签 | "挑战失败"（红色） |
| 操作区 | "重新挑战" 主按钮 + "换其他任务" 文字按钮 |

挽留态用户操作后：
- 点"重新挑战" → 任务进度归零，状态变为"进行中"
- 点"换其他任务" → 当前任务释放互斥锁，横条切换为"无进行中任务"（隐藏），用户可在账户卡片内选其他任务

### 3.5 实训账户卡片

**注意**：实训账户卡片在模拟账户卡片**上方**（实训优先策略）。

#### 3.5.1 卡片整体结构

| 区域 | 内容 |
|---|---|
| 标题区 | "实训账户" + 右侧箭头（点击跳实训账户详情）|
| 账户数据概览 | 4 个核心数据 |
| 任务区 | 进行中任务 / 推荐任务 |
| 底部入口区 | "现金奖励中心" + "补贴金中心" 并列 |

#### 3.5.2 账户数据概览（4 项）

| 数据 | 说明 |
|---|---|
| 账户规模 | 实训账户初始规模（如 "$5,000"）|
| 账户状态 | "运行中" / "已锁定" / "未启动" |
| 当前净值 | 实时净值（如 "$5,234.56"）|
| 持仓盈亏 | 当前未平仓持仓盈亏（如 "+$120.00"）|

视觉规则：
- 4 列等宽布局
- 数字字号 14px DINPro Medium
- 盈亏色彩：盈利 `#F44336` 红 / 亏损 `#2DC771` 绿（金融行业涨红跌绿）
- 状态标签色彩：运行中绿 / 已锁定橙 / 未启动灰

#### 3.5.3 任务区

**有进行中任务时**（可能是实训任务或现金挑战）：

仅展示**当前实训账户上的进行中任务**摘要（与顶部"当前任务横条"信息一致，但视觉融入卡片）。

> 注意：当前任务横条已经全局展示了进行中任务，账户卡片任务区可重复展示该任务（强化），也可隐藏。建议**重复展示**，让用户在浏览账户卡片时有完整上下文。

**无进行中任务时**：

展示**3 个推荐任务**横排：

| 元素 | 内容 |
|---|---|
| 任务卡 | 任务名 + 任务类型标签 + XP 奖励 |
| "查看更多"按钮 | 跳转 [06-推荐任务列表](./06-推荐任务列表.md)，按"实训账户"筛选 |

推荐任务来源：当前等级下、用户**未做过 + 未失效**的实训任务 + 已解锁的现金挑战，**按任务编号顺序前 3 个**。

#### 3.5.4 底部入口区

并列两个入口（左右均分）：

| 入口 | 跳转 |
|---|---|
| 现金奖励中心 | [07-现金奖励中心](./07-现金奖励中心.md) |
| 补贴金中心 | [08-补贴金中心](./08-补贴金中心.md) |

视觉：
- 圆角 8px
- 入口卡内含图标 + 名称
- 高度 56px

#### 3.5.5 用户没有实训账户时

整张卡片替换为"实训账户领取引导卡"：

| 区域 | 内容 |
|---|---|
| 标题 | "领取你的实训账户" |
| 描述 | "完成新手任务即可获得 $1,000 实训账户，开启实训之旅" |
| CTA 按钮 | "立即领取" |

点击 CTA → 跳转**实训账户领取 H5**（外部页面，详细流程不在本 PRD 范围）。

### 3.6 模拟账户卡片

#### 3.6.1 卡片整体结构

| 区域 | 内容 |
|---|---|
| 标题区 | "模拟账户" + 右侧箭头（点击跳模拟账户详情）|
| 账户数据概览 | 4 个核心数据 |

#### 3.6.2 账户数据概览

模拟账户的初始资金为 **¥500,000 人民币**（与实训账户的 $1,000 美元不同）。

| 数据 | 说明 |

| 账户规模 | 模拟账户当前规模（如 "¥500,000"）|

#### 3.6.3 任务区

### 3.7 任务数据概览

| 数据 | 说明 |

视觉规则：
- 横向 3 列均分
- 数字大字号（24px DINPro Medium）
- 文字下方为 "进行中" / "已完成" / "待开启" 标签

### 3.8 训练历史

| 元素 | 内容 |
|---|---|
| 标题区 | "训练历史" + 右侧"查看全部"链接 |
| 列表 | 默认展示**最近 3 条**已完成 / 失败 / 失效的任务记录 |

**账户兜底逻辑**（详见 [10-WebTrader 中转](./10-WebTrader中转.md) 第 4 节）：

## 4. 关键交互

### 4.1 下拉刷新

支持下拉刷新整个训练页所有数据。

### 4.2 任务互斥的全局约束

任务三类（日常 / 实训 / 现金）全局互斥，任意时刻用户只能进行 1 个任务。

UI 上不显式展示"灰态/锁定"，而是在用户尝试开启另一类任务时通过弹窗提示：

```
弹窗：
  标题：当前已有进行中任务
  正文：你正在进行 [任务名]，需要先完成或退出后才能开启新任务。
  按钮：取消 / 去查看当前任务
```

点击"去查看当前任务"跳转任务详情半框。

### 4.3 滚动行为

- 顶部导航栏始终固定
- 中间内容随滚动
- 底部"训练"按钮始终固定（位于底部 Tab 栏上方）

### 4.4 数据更新触发

| 触发场景 | 受影响数据 |
|---|---|
| 用户在 WebTrader 完成交易后回到 App | 实训 / 模拟账户净值、持仓盈亏 |
| 用户完成任务 | XP、等级、任务数据概览、训练历史 |
| 用户接新任务 | 当前任务横条、任务数据概览 |
| 用户收到新邀请阶段达成 | 成长模块（如邀请进度更新）|

## 5. 异常态

| 异常 | 表现 | 处理 |
|---|---|---|
| 任意区块接口失败 | 该区块加载失败 | 显示骨架屏 / "加载失败"占位 |
| 用户长时间无操作 | 各区块数据可能过期 | 切回前台时自动刷新关键数据（账户净值、任务状态）|
| 网络断开 | 全部数据无法加载 | 显示全局网络异常提示 |
| 实训账户接口失败 | 实训账户卡片无法显示 | 卡片显示骨架屏，其他区块正常 |

## 6. 接口约束

| 能力 | 说明 |
|---|---|
| 训练页聚合接口 | 返回训练页所需的全部数据（推荐）：等级、XP、邀请进度、双账户数据、当前任务、训练历史摘要、任务概览 |
| 任务推荐接口 | 返回当前等级下未做过的推荐任务列表 |
| WebTrader token 获取 | 详见 [10-WebTrader 中转](./10-WebTrader中转.md) |
| 实训账户领取入口 | 返回外部 H5 链接 |

接口的具体定义、字段、协议由后端开发设计，本文档仅描述业务诉求。

**性能要求**：

- 首屏关键数据（等级、双账户、当前任务）应在 1 秒内呈现
- 推荐使用聚合接口减少首屏请求数
